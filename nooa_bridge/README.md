# Мост к NOOA — мозг агента от NVIDIA

Подключает [NVIDIA-labs OO Agents](https://github.com/NVIDIA-NeMo/labs-OO-Agents)
как **мозг** автономного Макса. Руки при этом остаются свои — `mark17/hands.py`
с белым списком и границами проекта. NOOA решает, что делать; выполняет всё
равно Макс, и только разрешённое.

## Почему отдельным процессом, а не внутри ядра

| | |
|---|---|
| NOOA требует | Python **≥3.12** |
| Ядро Макса на Маке | Python **3.9** |

Втащить NOOA в `mark17` нельзя без перевода всего ядра на 3.12 — это ломает
всё остальное. Плюс NOOA тянет `litellm` и его зависимости, а ядро сейчас
обходится стандартной библиотекой, и это его сильная сторона.

Поэтому NOOA живёт в своём окружении и отвечает по HTTP — тот же приём, что
с мостом Max17. Нет моста — Макс решает сам, своими правилами: автономность
не пропадает, просто становится проще.

## Установка (один раз)

Нужен Python 3.12+. Проверить:

```
python3.12 --version
```

Нет — поставить: `brew install python@3.12`

Дальше:

```
cd nooa_bridge
python3.12 -m venv .venv
.venv/bin/pip install -U pip
.venv/bin/pip install nooa
```

## Запуск

Мозг на локальной модели, без ключей и без интернета:

```
NOOA_MODEL="ollama_chat/qwen3:1.7b" NOOA_API_BASE="http://localhost:11434" .venv/bin/python server.py
```

Или на облачной модели:

```
ANTHROPIC_API_KEY=... NOOA_MODEL="claude-haiku-4-5" .venv/bin/python server.py
```

Проверить, что поднялся:

```
curl -s http://127.0.0.1:8791/health
```

## Как это видит Макс

Ядро само ищет мост по `MAX17_NOOA_URL` (по умолчанию `http://127.0.0.1:8791`).
Если мост отвечает — решения принимает NOOA. Не отвечает — правила ядра.
Переключение молчаливое, ронять переписку из-за недоступного мозга нельзя.

## Границы

NOOA **не получает** доступа к оболочке. Он возвращает только имя действия из
списка `hands.describe()` и его параметры; выполняет `hands.act()` с теми же
проверками, что и всегда: белый список команд, пути внутри проекта, отсутствие
оболочки, журнал попыток.

Это сделано намеренно: у NOOA есть собственные инструменты выполнения
(`nooa.tools.shell_tools`, `_bash_session`), и они мощнее — но тогда границы
задавал бы не ты, а чужой фреймворк. Здесь мозг чужой, руки свои.
