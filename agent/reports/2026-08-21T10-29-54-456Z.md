**1. Сайт отвечает 5.3 секунды — критично**

Признак: внешний пинг mir.care = 5.289s.
Причина видна из `app/page.tsx:32` — `export const dynamic = 'force-dynamic'` отключает кэш Next.js, и каждый запрос делает полный SSR 30+ компонентов. Дополнительно `app/api/llm-config/route.ts:75` на каждый GET поднимает дочерний Python-процесс (`spawn python3 llm_config.py`) с таймаутом 15 секунд — если его вызывают при загрузке, это прямой вклад в задержку.
Предложение: убрать `force-dynamic` для статичной оболочки страницы (компоненты загружают данные сами через fetch на клиенте), либо кэшировать ответ llm-config (он меняется редко).

---

**2. RAM 413 МБ свободно из 961 МБ — тесно**

Признак: 57% памяти занято при 4 запущенных процессах.
Причина: `vector_memory.py:36` держит в памяти до 8000 записей (`RECALL_CAP`) плюс numpy-массивы для ANN-индекса; с 1.1 ГБ памяти ядра на диске пересборка индекса (`forge_vectors`) может временно удвоить потребление.
Предложение: снизить `MAX17_RECALL_CAP` до 4000–5000 в .env, пока RAM не будет расширена; добавить мониторинг порога (например, alert при < 200 МБ).

---

**3. llm-config spawns Python на каждый GET — латентность и fork-bomb риск**

Признак: `app/api/llm-config/route.ts:73–106` — `runLlmConfig()` делает `spawn()` без ограничения на параллельные вызовы.
Причина: нет очереди или дедупликации; при параллельных запросах (несколько вкладок, боты) одновременно поднимаются несколько Python-процессов.
Предложение: кэшировать результат на 30–60 секунд на стороне Node (простой `let cache = {value, ts}`), либо перевести в Unix-socket к уже живому Python-процессу.

---

**4. `ultra_orchestrator.py` действие `hands` уходит в реальность без блокировки**

Признак: `ultra_orchestrator.py:43` — `"hands"` в `ALLOWED_ACTIONS`; решение принимает LLM, ограничения только декларативные (строки в `_ACTION_CONSTRAINTS`).
Причина: если gonka-deepseek вернёт `"action": "hands"` с нежелательным запросом — нет технического барьера до исполнения.
Предложение (догадка): убедиться, что в `json_cli.py` действие `hands` создаёт запись-заявку для человека и ждёт подтверждения, а не исполняется автоматически. Стоит проверить этот путь явно.
